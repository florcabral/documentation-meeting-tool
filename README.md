# Docs Decision Tool

A lightweight web app for running structured documentation decisions during live remote meetings. Built with React + Vite, Vercel serverless functions, and Vercel KV.

## What it does

- Facilitator loads proposals before the meeting (or generates them with `/propose`)
- Teammates open a single URL on their own devices — no account needed
- Everyone votes (+1 / -1), comments, and proposes alternatives in real time
- The overview tab updates live — polling every 4 seconds
- After the meeting, `/summarize` writes `discussion.md` with the full decision record

## Pre-build setup

Before running the app, complete these four steps:

### 1. Create a private GitHub repo

```bash
git clone <your-repo-url>
cd <repo-name>
```

### 2. Create Vercel project + KV (Upstash Redis)

> **Note:** Vercel KV has migrated to Upstash Redis. Existing KV stores appear under Vercel Integrations. For new projects, add an Upstash Redis integration from the Vercel Marketplace — the API is compatible and the same `@vercel/kv` package works with it.

1. Go to [vercel.com](https://vercel.com) → New Project → import the GitHub repo
2. Don't deploy yet — just connect it
3. Go to **Integrations** → search "Upstash Redis" → add free tier → Connect to project
4. Pull credentials locally:

```bash
npm i -g vercel
vercel link
vercel env pull
```

`vercel env pull` writes `.env.local` with your KV credentials. This file is already in `.gitignore`.

### 3. Enable GitHub Pages

GitHub repo → **Settings → Pages → Source: GitHub Actions**

The deploy workflow is already set up at `.github/workflows/deploy.yml`.

### 4. Install dependencies and start

```bash
npm install
npm run dev   # runs vercel dev (frontend + API + KV)
```

## Cursor AI slash commands

| Command | What it does |
|---|---|
| `/review` | Parses `proposals.md` → writes `session.json` → app loads proposals on next poll |
| `/propose` | Takes pasted raw context → generates `proposals.md` → runs `/review` automatically |
| `/summarize` | Fetches live vote data → writes `discussion.md` with full decision record |

### Before the meeting — option A (existing proposals)

1. Edit `proposals.md` with your proposals (H2 headings = proposal titles)
2. Run `/review` in Cursor
3. Start `npm run dev` and share the URL

### Before the meeting — option B (from scratch)

1. Run `/propose` in Cursor and paste raw context (notes, Google Doc text, a brief)
2. Cursor generates `proposals.md` and loads it automatically
3. Start `npm run dev` and share the URL

### After the meeting

Run `/summarize` in Cursor. It fetches the final vote state and writes `discussion.md`.

## File structure

```
.cursor/
  rules/         ← /review, /propose, /summarize triggers
  prompts/       ← detailed instructions for each command
  skills/        ← proposals.md format spec

api/
  proposals.js   ← GET/POST proposals
  votes.js       ← GET/POST votes
  comments.js    ← GET/POST comments
  summarize.js   ← GET all session data (for /summarize)
  _kv.js         ← shared KV helpers

src/
  App.jsx        ← main app shell, polling logic
  components/
    TabBar.jsx   ← tab navigation + add proposal form
    OverviewTab.jsx
    ProposalTab.jsx
    NameModal.jsx

proposals.md     ← facilitator writes proposals here
session.json     ← generated by /review, read by app on load
discussion.md    ← generated by /summarize after the meeting

.github/workflows/deploy.yml   ← GitHub Pages deploy
vercel.json                    ← Vercel build config
```

## Data model (Vercel KV)

Keys are namespaced by session ID (date-based, from `session.json`):

- `session:{id}:proposals` — array of `{ id, title, body, author, createdAt }`
- `session:{id}:votes` — array of `{ proposalId, author, value, createdAt }`
- `session:{id}:comments` — array of `{ proposalId, author, text, createdAt }`

One vote per author per proposal — re-voting overwrites the previous vote.
